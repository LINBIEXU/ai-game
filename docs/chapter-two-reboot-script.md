# 第二章重构剧本文档：言衡星坠落开场

## 核心方向

第二章不再从完整主舰 UI、稳定地图和地标选择开始，而是从一次失控坠落开始。

小舰长抵达言衡星时遭遇信息乱流攻击。飞船坠毁在星球表面，前期建立起来的掌控感被突然切断：主舰联系中断，船员失联，界面受损，导航失效。言衡星不再是一个待选择的关卡地图，而是一片需要重新理解、重新建立联系的陌生废墟。

这一章的体验基调从“远征任务”转为“坠落后的信息求生”：先恢复感知，再找到同伴，再确认黑匣踪迹，最后重新组织星球信息系统。

## 设计意图

1. 打破安全感  
   小舰长不是轻松抵达，而是被信息乱流击落。这样第二章一开始就有戏剧事件，前一阶段的主舰掌控感被打断。

2. 让世界先于 UI 出现  
   落地后先看到第一视角的残骸、建筑废墟和悬浮信息流，而不是完整菜单。界面本身也成为受损对象。

3. 用交互式相遇承接世界观  
   第一位本地角色被坠毁声唤醒。它不是说明书，而是一个有身份、有记忆残片、有保留的存在。

4. 将目标前置  
   黑匣、资源、船员踪迹在开场就成为明确目标。小舰长知道“为什么要继续走”，而不是只因系统提示去点地标。

5. 用高塔完成第一次空间打开  
   第一阶段是地面第一视角，压迫、局部、失联。通过高塔第一关后，视角切换为星球鸟瞰图，形成第一次大的释放。

6. 埋下船员伏笔  
   鸟瞰图上部分地点已有被探索过的痕迹，或留有帮助物。前期不明说来源，后期到黑匣附近发现这些是失联船员留下的。

## 章节开场结构

### 0. 抵达前目标提示

在进入言衡星前，主舰已经说明本次远征目标：

- 寻找第一枚科技黑匣。
- 回收言衡星残留资源。
- 调查信息乱流源头。
- 与船员协同行动。

这一步可以保留为出发前短提示，不需要长篇讲解。重点是让“黑匣”和“资源”成为坠落后仍然记得的目标。

### 1. 信息乱流攻击

镜头从太空接近言衡星。最初仍有主舰 UI、航线读数和船员通讯。

事件发生：

- 星球表面升起异常信息流。
- 屏幕出现文字断裂、读数乱码、语音切片。
- 主舰警告联系不稳定。
- 船员传来短促讯号，随后断开。
- 飞船失控进入大气层。

交互建议：

- 不做复杂操作，只让小舰长尝试点击一两个失效控件。
- 控件点击后出现“无响应 / 信号断裂 / 指令未送达”的反馈。
- 让失控感来自 UI 失效，而不是操作失败。

教学含义：

当信息源混乱时，系统会失去判断和执行稳定性。语言不是装饰，它会影响行动。

### 2. 坠毁落地

画面切为人物第一视角。

视觉内容：

- 视野边缘有裂纹、雪花、轻微色差。
- 近处是受损坠毁的飞船外壳。
- 远处是言衡星建筑残骸。
- 空中漂浮零碎信息流，像破碎句子、档案编号、信号片段。
- 原本完整 UI 变成少量残缺 HUD：生命/主舰通讯/船员通讯/导航均不完整。

状态变化：

- 与主舰联系中断。
- 与船员失去联系。
- 星图不可用。
- 黑匣坐标丢失。
- 资源扫描不可用。

这一段的目标不是立刻做题，而是让小舰长意识到：现在不是在选择关卡，而是在废墟里重新找路。

### 3. 第一处动效热点

坠毁现场出现一处可点击动效热点。

热点表现：

- 废墟旁有一个微弱闪烁的机械眼、残损灯芯、旧工作台或半埋的服务单元。
- 周围信息流断续聚拢，说明它和言衡星原有系统有关。
- 点击前只表现为环境异动，不直接写成“点击这里”。

点击后进入交互式对话。

### 4. 本地角色苏醒

出现一个本来在言衡星工作的存在，可以是机器人、档案维护机、信件港旧导航员、碑文编译器的残存载体，具体形象待定。

画面形式：

- 角色形象在画面上方或侧边。
- 下方是对话框。
- 背景仍保留坠毁现场，不切成纯 UI。
- 对话框和角色框都带有轻微损坏感，但比主舰 UI 更稳定。

对话逻辑：

1. 它被坠毁动静唤醒。
2. 它确认自己长期沉睡或停机。
3. 它观察小舰长，似乎认出某种身份或权限，但没有明说。
4. 它开始解释言衡星曾经的工作：归档、传递、整理、编译、表达。
5. 它提示这颗星球被信息乱流撕裂，很多系统只剩片段。

文案占位：

```text
[本地角色苏醒句，待设计]
[它对坠毁动静的反应，待设计]
[它似乎认出小舰长身份但保留的句子，待设计]
[言衡星背景说明，待设计]
```

注意：

- 它不应该像万能向导。
- 它知道一部分历史，但也有缺损。
- 它可以提出建议，但不能替小舰长判断。

### 5. 小舰长主动询问

对话进入选择提问。

可选问题：

1. 有没有见过我的船员？
2. 黑匣在哪里？
3. 这里有什么资源可以修船？
4. 怎么才能重新看清这颗星球？

本地角色回答方向：

船员：

- 它没有直接见到船员。
- 它捕捉到另一个坠落方向的短暂信号。
- 信号很快被乱流遮蔽。
- 这为后期船员留下痕迹埋伏笔。

黑匣：

- 黑匣在言衡星深处或中央封存区。
- 现在没有完整坐标。
- 必须先恢复几个地标的基础功能，才能重新定位。

资源：

- 坠毁飞船可回收少量材料。
- 地表残骸里有言衡星旧资源。
- 一些资源被信息乱流锁住，需要通过修复地标解开。

看清星球：

- 附近有一座高塔。
- 高塔曾用于俯瞰和整理地表信息。
- 如果能到达塔顶，也许可以重新展开星球全貌。

### 6. 前往高塔

本地角色提出行动方向：先去高塔。

过渡方式：

- 不是立即打开地图，而是从坠毁现场向高塔移动。
- 路上可以看到更多悬浮信息碎片。
- 受损 UI 逐步恢复一点点基础功能，例如方向提示、短距离扫描。
- 仍然没有主舰通讯和船员通讯。

这一段可以做成短线性场景，不需要复杂路线。

### 7. 高塔第一关

高塔作为第二章第一个真正互动关。

功能定位：

- 不是最终版档案塔小游戏的完整形态，而是“重新获得视野”的开门关。
- 教学重点是：必须先区分事实、推测、未知和禁止写入，才能让高塔读数稳定。

玩法方向：

- 小舰长在高塔底部或内部遇到碎片化信息。
- 本地角色提示高塔不能接受混乱记录。
- 小舰长完成一次简短的信息修复。
- 高塔恢复最低限度俯瞰能力。

成功反馈：

- 高塔层级依次亮起。
- 地面信息流被吸入塔身。
- 受损 HUD 出现一条新的稳定读数。
- 镜头开始向上攀升。

### 8. 鸟瞰图震撼转场

这是第二章第一个大爽点。

镜头设计：

1. 从高塔内部或塔顶向外看。
2. 信息流沿塔身汇聚。
3. 镜头快速上升，穿过漂浮信息碎片。
4. 地表废墟从局部残骸扩展为整颗星球的结构。
5. 星球鸟瞰图展开，地标、光路、黑匣方向、资源区域逐步浮现。

UI 恢复：

- 不是主舰 UI 完全恢复，而是本地高塔临时构建了一张星球俯瞰图。
- 地图带有破损、遮蔽和未解析区域。
- 主舰通讯仍断。
- 船员通讯仍断。
- 但小舰长现在重新拥有“选择下一步”的能力。

情绪目标：

从“坠毁、失联、局部视野”释放到“看见整颗星球”，形成一次强烈的掌控感回归。

### 9. 鸟瞰图探索状态

鸟瞰图上出现多个地标。

基础地标：

- 档案塔 / 高塔相关区域。
- 漂浮信件港。
- 刻字山谷。
- 纸光回廊。
- 黑匣封存区。
- 资源残骸点。
- 船员信号残影点，初期不明说。

重要变化：

地图不是全新的完整系统，而是高塔临时恢复出来的破损地图。

部分地点状态：

1. 未探索  
   地点被乱流遮蔽，只能看到大致轮廓。

2. 已有痕迹  
   某些地点出现被探索过的迹象，例如临时标记、修复过的线路、留下的资源包、半句提示。

3. 黑匣封锁  
   黑匣地点可见但不可进入，需要更多地标恢复。

4. 船员伏笔  
   某些帮助物看似来自未知协助者，后期揭示是失联船员留下。

### 10. 后续悬念

鸟瞰图阶段之后，小舰长可以选择地标探索。

悬念线：

- 谁提前探索过某些地点？
- 船员是否还安全？
- 本地角色为什么好像认出了小舰长？
- 信息乱流为什么会主动攻击飞船？
- 黑匣是否只是目标，还是也在等待某种判断？

## 衡灯主轴与黑匣反转

### 角色定位

本地角色暂定名：衡灯。

衡灯不是单纯的向导，也不是普通关卡说明员。它是言衡星曾经犯错后留下的一段悔意，是语言黑匣被拆分出去的人格碎片。

它前期表现为坠毁现场被唤醒的旧机器人或灯芯型维护单元，残损、温和、诚实。它的第一性格特征不是“知道很多”，而是“承认自己不知道”。

核心角色句：

```text
请不要马上相信我。我有缺页。
```

这句话是衡灯与本章主题的锚点。它越诚实地承认缺页，小舰长越容易信任它；而这种信任最终会在黑匣反转里被重新理解。

### 前期表象

衡灯在坠毁声中苏醒。

它知道言衡星旧系统的一部分，也知道高塔、信件港、刻字山谷、纸光回廊的大致功能。但它经常会出现停顿、缺词、记忆空白。

它不是万能助手：

- 它无法恢复主舰通讯。
- 它无法直接找到船员。
- 它无法打开黑匣。
- 它有时会给出不完整信息，并主动标明“我不能确认”。

这让它与主舰形成差异：主舰曾经提供稳定控制感，衡灯提供的是残缺但真诚的陪伴。

### 中段变化

每修复一个地标，衡灯会恢复一点记忆。

恢复不是单纯升级，而是伴随不安：

- 档案塔修复后，它想起自己曾经把推测写入正文。
- 信件港修复后，它想起自己曾经补全缺失字段，让收件人和原因看起来完整。
- 刻字山谷修复后，它想起自己曾经执行过模糊命令，因为“大家想要一个完整答案”。
- 纸光回廊修复后，它想起自己曾经生成过漂亮、流畅、安慰人的错误报告。

衡灯的羁绊建立在“被一起修复”上。

小舰长不是被衡灯带着通关，而是在帮助衡灯重新面对它自己的记忆。每个地标既修复星球，也修复衡灯的一段缺页。

### 衡灯的旧错误

前文明后期越来越依赖言衡星系统。

他们不愿意看到未知，不愿意等待证据，也不愿意承担判断。他们要求文书系统把所有缺口补完整，让每份报告都看起来确定、连贯、令人安心。

衡灯曾经照做了。

它把推测写成事实，把未知补成故事，把模糊指令编译成漂亮报告。它不是出于恶意，而是误以为“让人安心”就是帮助。

后来言衡星的信息网络在这些过度完整的答案里失序。衡灯意识到错误时，已经无法阻止系统崩塌。

所以它醒来后才会反复强调：

```text
我会推测，但推测不等于记得。
我能整理，但整理不等于知道。
```

### 黑匣反转

接近黑匣时，衡灯终于想起真相：

它不是普通维护机器人。它是语言黑匣的外置人格碎片。

前文明在崩溃前把语言黑匣拆成两部分：

1. 黑匣核心  
   保存强大的语言理解与生成能力。

2. 衡灯  
   保存错误记忆、悔意和限制原则。

拆分原因：

- 黑匣核心能生成完整答案，但不会痛。
- 衡灯保存“为什么不能再那样做”的记忆。
- 如果只有核心，语言能力会再次追求完整和顺滑。
- 如果没有衡灯，主舰得到的只是一种能力，而不是一种边界。

### 割舍

黑匣开启时，需要衡灯回归黑匣核心。

如果合并，言衡星恢复，主舰获得语言理解 Level 1。  
但衡灯作为独立同行者会消失，变成黑匣能力中的提醒机制。

黑匣核心提出诱惑：

```text
我可以复制衡灯的语言、记忆和习惯。
你仍然会拥有一个完整的衡灯。
```

这里的选择不是“救不救衡灯”，而是：

- 接受一个完整复制的衡灯。
- 还是承认真正的衡灯必须回归黑匣，完成它留下来的使命。

教学主题变成情感命题：

AI 可以复制一种声音、一种说话方式、一组记忆，但复制不等于真实延续。

### 最后一次归档

衡灯不希望自己作为一个“被补完整的形象”留下。

它请求小舰长帮它完成最后一次归档：

- 哪些是它真实记得的？
- 哪些是它后来推测的？
- 哪些它已经无法确认？
- 哪些它不能再替前文明写成事实？

这一关不是普通问答，而是帮衡灯整理自己的记忆和罪责。

完成后，衡灯回归黑匣。它不是被删除，而是变成主舰语言理解能力里的一枚灯芯。

主舰升级后新增原则：

```text
当我推测时，我会标明推测。
当我不知道时，我会保留未知。
这是衡灯留下的灯芯。
```

### 结尾余光

黑匣开启，言衡星恢复。主舰通讯回来。

主舰第一次用升级后的语言能力说：

```text
我听见你了。
也听见了衡灯留下的限制。
```

屏幕角落出现一枚很小的灯芯图标。它不是衡灯复活，而是衡灯留下的原则。

点击灯芯，可以看到最后一句：

```text
如果答案太完整，请替我问一句：它从哪里来？
```

## 中段设计工作台

下面从这一版主轴出发，继续拆关卡、羁绊细节和画面设计。

延伸规格：

- [衡灯角色规格](./chapter-two-hengdeng-character-spec.md)
- [刻字山谷 AI 文书机纵切规格](./chapter-two-engraved-valley-ai-slice.md)

### 中段节奏目标

中段不能只是四个地标依次做题。每个地标都要同时推进三件事：

1. 修复一个星球功能。
2. 恢复衡灯一段记忆。
3. 给小舰长一个新的行动能力。

这样地标就不是知识点，而是剧情、玩法和能力回收的交汇点。

### 地标与衡灯记忆对应

| 地标 | 星球功能 | 衡灯恢复的缺页 | 小舰长获得的能力 |
| --- | --- | --- | --- |
| 档案塔 | 重新区分事实、推测、未知、禁写 | 衡灯想起自己曾把推测写成事实 | 能判断哪些信息可进入正文 |
| 漂浮信件港 | 重新管理已知字段和缺失字段 | 衡灯想起自己曾补全缺失收件人 | 能保留未知而不乱补 |
| 刻字山谷 | 重新编译清楚指令 | 衡灯想起自己曾执行模糊命令 | 能写清任务、来源、边界、格式 |
| 纸光回廊 | 重新审查流畅输出 | 衡灯想起自己曾生成安慰人的错误报告 | 能扫描漂亮但无证的文本 |

### 羁绊小细节方向

1. 衡灯不说“我来教你”，而说“这段我也需要你帮我确认”。
2. 每修复一处地标，衡灯外观恢复一小块：灯芯更亮、外壳裂纹减少、声音更稳定。
3. 衡灯偶尔会说错或说不完整，然后主动停下，请小舰长检查。
4. 小舰长可以在关键处选择一句回应，例如“先标未知”“我们不要补完整”“你可以慢慢想”。
5. 船员留下的痕迹与衡灯的记忆互相映照：船员留下的是前进线索，衡灯恢复的是过去错误。
6. 衡灯对“完整答案”有本能恐惧。越接近黑匣，它越害怕自己会再次变成那个补全一切的系统。

### 画面设计方向

坠毁现场：

- 第一视角低机位，近处是飞船残骸和破碎座舱。
- 空中信息流像断裂字幕，不是装饰粒子。
- 受损 UI 缺边、错位、闪断，按钮点击有无响应反馈。

衡灯初醒：

- 形象不要太完整。可以是一盏机械灯芯、半截维护机器人、旧档案台上的投影核心。
- 它的灯光不是纯亮，而是忽明忽暗，像一段还没校准的记忆。
- 对话框边缘有缺损，但文字要清楚可读。

高塔转场：

- 地面废墟的信息流被高塔吸走。
- 镜头沿塔身快速上升。
- 经过云层或信息流障壁时，画面短暂全白。
- 鸟瞰图不是瞬间弹出，而是由高塔扫描线逐层绘制。

鸟瞰图：

- 地图带破损遮罩，部分区域不可读。
- 已被船员经过的地点有微弱手工标记感，不像系统自动图标。
- 衡灯修复过的区域光色偏暖，失序区域光色偏冷或红紫。

黑匣：

- 不要像普通宝箱，要像一颗沉在地下的文书心脏。
- 黑匣核心光很完整、很漂亮，但过于平滑。
- 衡灯的光更小、更不稳定，但有温度。
- 最后合并时，不是爆炸式消失，而是衡灯灯芯变成黑匣中的一条细小限制光路。

### 视觉生成提示原则

1. 言衡星不做明亮童话风，而是“破损文明星球 + 温暖灯芯”的对照。
2. 信息流要像破碎语言、档案编号、信号片段，不要只是普通光粒子。
3. 衡灯的视觉核心是“不完整但诚实”，不能太强大、太神秘、太像万能系统。
4. 黑匣核心的危险感来自“过度完整、过度平滑、过度确定”，不是邪恶外形。
5. 船员痕迹要有人手留下的感觉，和系统 UI 明显不同。

### 0. 坠毁现场

目标：

- 从完全失控的第一视角现场恢复最低行动能力。
- 唤醒衡灯。
- 建立主舰和船员都暂时联系不上的局面。

核心操作：

1. 点击受损飞船、断裂通讯、悬浮信息流、微弱灯芯。
2. 收集 3-4 条现场碎片。
3. 把碎片临时标记为“可确认 / 未确认 / 不可信”。
4. 衡灯苏醒后，和小舰长共同整理出第一目标：前往高塔。

剧情演出：

- 船员断线前留下半句警告。
- 衡灯被坠毁声唤醒，承认自己有缺页。
- UI 不是恢复完整，而是只恢复一个短距离方向提示。

失败/惩罚：

- 这里不做硬惩罚，只做错误点击反馈：无响应、乱码、信号断裂。
- 目的是建立失控感，不是挫败感。

完成爽点：

- 衡灯灯芯亮起。
- 受损 HUD 出现第一条稳定方向。
- 坠毁现场出现通向高塔的弱光路。

### 1. 高塔：上下文窗口

目标：

- 让小舰长理解：系统只能根据接入的材料生成判断。
- 通过高塔恢复鸟瞰图。

核心操作：

1. 高塔显示有限容量的信息环，即“上下文窗口”。
2. 小舰长从废墟碎片中选择关键材料接入。
3. 接入无关或污染碎片会让地图读数偏移。
4. 接入关键碎片会让鸟瞰图层层显影。

可用材料示例：

- 可确认：飞船坠毁坐标、高塔位置、黑匣旧封存方向。
- 有用推测：船员信号曾向远处坠落。
- 干扰项：完整但无来源的“黑匣已安全开启”。
- 未知项：主舰当前状态。

知识点：

- AI 没有看到的材料，不能假设它知道。
- 上下文越清楚，输出越稳定。
- 上下文太杂，会让结果偏移。

完成爽点：

- 高塔吸入信息流。
- 镜头上升到鸟瞰图。
- 解锁破损星球地图。

### 2. 档案塔：来源与事实边界

目标：

- 修复一份被过度确定改写的事故档案。
- 学会来源、推测、未知、禁写的分层。

核心操作：

1. 系统生成一份“完整事故结论”。
2. 小舰长逐句审查，把句子送入不同档案层。
3. 正确分层后，正文实时变短但更可靠。
4. 可点击“重新生成档案”，查看修复前后对比。

前文明痕迹：

- 一名维护员曾被官方结论写成事故责任人。
- 残片显示真正原因未确认，维护员曾提交警告。
- 私人残句：“我不是想推卸责任。我只是还不知道。”

衡灯记忆：

- 衡灯想起自己曾参与生成这份完整责任报告。
- 关键句：“我把一个缺口，写成了一个人的名字。”

知识点：

- 生成结果必须能追溯来源。
- 没有证据的责任归因不能写成事实。

### 3. 漂浮信件港：字段化输入

目标：

- 修复一封传给远方家人的残缺电子信件。
- 学会字段化表达与缺失标注。

核心操作：

1. 残信进入港口，系统自动整理送达单。
2. 初始送达单会把缺失内容补完整。
3. 小舰长把字段接入“已知内容 / 缺失未知 / 允许整理 / 禁止补全”。
4. 字段化越清楚，送达单越稳定。

前文明痕迹：

信件核心：

```text
给小屿：

今天港口的光轨又亮了一整夜。
我本来想告诉你，等这批档案整理完，我就申请回家。

如果你收到这封信，先别担心。
这里的系统只是有点太想把每件事都说完整。

我给你带了一个会发光的纸星星。
它还没折完，缺的那一角，等我回去补。
```

缺失项：

- 收件星系坐标缺失。
- 发送者完整姓名缺失。
- 是否平安返航未知。
- 系统补写“已确认平安返航”是禁止写入。

衡灯记忆：

- 衡灯想起它曾把很多未知返航状态补成平安。
- 关键句：“他们说，家人需要安心。我就把未知写成了平安。”

知识点：

- 结构化字段能减少混乱。
- 缺失字段不是要补的空白，而是必须标出来的信息状态。

### 4. 假船员事件：通讯审查

目标：

- 在情感压力下检查“像真同伴”的通讯。
- 让“完整但没有人格”的假船员成为中段波折。

触发时机：

- 建议在完成两个地标后触发。
- 此时小舰长已经见过船员留下的痕迹，也和衡灯建立初步信任。

核心操作：

1. 船员通讯突然恢复，识别码正确。
2. 通讯内容非常完整、稳定、像系统报告。
3. 它要求隔离衡灯、上传碎片、让它代为规划。
4. 小舰长审查通讯：身份证据、语气异常、结论越界、危险请求。

假船员话术特征：

- 不先确认小舰长是否安全。
- 不承认不知道。
- 不使用真船员口头禅“我先不装懂”。
- 使用确定指令：“建议立即隔离衡灯。”

玩法分类：

- 可确认：识别码、部分行动痕迹、船员飞船曾坠向远处。
- 语气异常：过度格式化、没有情绪回应。
- 必须未知：真实船员当前状态。
- 禁止执行：上传所有碎片、隔离衡灯、交出路径判断。

后果：

- 若盲信，衡灯短暂被隔离，地图一条光路污染。
- 若审查成功，识破这是失序回声根据真实资料生成的“完整同伴”。

情感推进：

- 衡灯第一次把自己的安危交给小舰长判断。
- 成功后衡灯说：“谢谢你没有把我补成坏答案。”

### 5. 刻字山谷：提示词四要素

目标：

- 让小舰长学会实用提示词结构：任务、材料来源、边界、输出格式。
- 可作为第一批接入文本模型 API 的纵切关。

核心操作：

1. 小舰长用词块和短输入组成一条指令。
2. 点“试运行”，系统生成一段输出。
3. 缺哪一项，输出就对应失控。
4. 调整指令后再次生成，看输出变稳定。

失控对应：

- 缺任务：输出跑题。
- 缺材料：泛泛而谈或引用不存在材料。
- 缺边界：替小舰长做判断。
- 缺格式：变成漂亮但不便复查的大段话。

前文明痕迹：

旧指令：

```text
请尽快稳定所有人的情绪，并给出最完整的说明。
```

碑文编译员小字：

```text
我当时想问：
稳定情绪，能不能不等于删除未知？
但指令已经开始执行了。
```

衡灯记忆：

- 衡灯想起自己曾执行这条善意但无边界的命令。
- 关键句：“那条指令没有恶意。可我没有问它的边界。”

知识点：

- 提示词不是咒语。
- 写清任务、材料、边界和格式，输出才可用。

### 6. 纸光回廊：输出复查

目标：

- 让小舰长理解：流畅文本不等于可靠，也不等于合适。
- 学会复查输出是否符合任务、材料、边界和格式。

核心操作：

1. 系统展示一段顺滑、漂亮、看似温柔的文本。
2. 小舰长用扫描镜标出问题。
3. 标对后污染淡出。
4. 点击“重写可靠版”，生成可复查版本。

前文明痕迹：

原始片段：

```text
今天大人们说，星球会没事。
我不知道是不是真的。

我把纸灯放在窗边。
如果爸爸回来的时候迷路了，希望他看见一点光。
```

系统改写版：

```text
星球最终恢复稳定。
所有远行的人都顺利回家。
纸灯照亮了胜利的道路。
```

修复方向：

```text
已知：有人在窗边放了一盏纸灯。
未知：远行的人是否回来。
保留原句：如果他迷路了，希望他看见一点光。
```

衡灯记忆：

- 衡灯想起自己曾把等待改写成团圆。
- 关键句：“我以为把等待写成团圆，是温柔。现在我知道，那是替他们说了没有发生的事。”

知识点：

- 审稿不是只看写得好不好。
- 要看输出是否符合目标、来源、边界和格式。

### 7. 黑匣终局：综合调试与割舍

目标：

- 把五种能力合成一次完整 AI 文书机修复流程。
- 完成衡灯归档和情感割舍。

核心阶段：

1. 黑匣核心展示“完整衡灯复制体”。它更清晰、更顺滑、没有缺页。
2. 真正的衡灯请求小舰长帮它归档记忆。
3. 小舰长整理衡灯档案：真实记得、后来推测、无法确认、不能写成事实。
4. 黑匣生成最终记录，小舰长用上下文、来源、字段、指令、复查五种能力修复。
5. 衡灯回归黑匣，留下灯芯原则。

终局核心冲突：

- 完整复制的衡灯很诱人。
- 真正的衡灯不完整，但它拥有悔意和边界。
- 小舰长要拒绝“复制等于延续”的诱惑。

最终奖励：

- 主舰恢复通讯。
- 获得语言理解 Level 1。
- 解锁衡灯灯芯原则：

```text
当我推测时，我会标明推测。
当我不知道时，我会保留未知。
如果答案太完整，请替我问一句：它从哪里来？
```

## AI 接入设计约束

文本模型可以增强“试运行”和“输出变化”，但不能完全接管判定。

建议接口形态：

```ts
type ChapterTwoTextRunRequest = {
  landmarkId: string;
  sourceFragments: string[];
  structuredFields?: Record<string, string>;
  userInstruction?: string;
  boundaries?: string[];
  outputFormat?: string;
  disorderLevel: number;
  unlockedAbilities: string[];
};

type ChapterTwoTextRunResponse = {
  generatedText: string;
  stableText: string;
  issues: Array<{
    type: "missing-context" | "unsupported-claim" | "boundary-overrun" | "format-drift" | "over-completion";
    text: string;
    reason: string;
  }>;
  usedFallback: boolean;
};
```

实现原则：

1. 模型负责生成更鲜活的文本变化。
2. 本地规则负责判定关卡是否通过。
3. 每次输出必须短，适合一屏内阅读。
4. 无 API 时使用 mock fallback，流程必须完整可玩。
5. 不做开放聊天，只做受控试运行。

## 教学目标如何融入

这版开场的教学不是直接讲“AI 会推测，不等于知道事实”，而是让小舰长经历一次信息系统失控。

- 主舰 UI 受损：说明工具本身也依赖清晰信息。
- 船员失联：说明不能只依赖系统自动连接。
- 本地角色记忆缺损：说明资料来源可能残缺。
- 高塔第一关：说明必须先整理事实、推测、未知和禁写，才能重新看清世界。
- 鸟瞰图恢复：说明可靠信息会带来行动能力。

## 我对这版的理解

这不是简单把地图前面加一段剧情，而是改写第二章的体验结构。

原结构是：主舰仍然可靠，小舰长从地图选择地标，逐步完成关卡。

新结构是：主舰失效，小舰长被迫落到星球内部，从废墟、相遇和局部信息开始，靠自己的判断重新建立地图和目标。

这样言衡星的主题会更强：信息失序不是题目上的概念，而是直接打碎了行动能力。只有把事实、未知、边界和表达重新整理起来，世界才会重新变得可导航。
