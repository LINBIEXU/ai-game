# 刻字山谷 AI 文书机纵切规格

## 纵切目的

刻字山谷作为第一条 AI 文本玩法纵切，用来验证新版言衡星的核心循环：

```text
整理材料 → 写清指令 → 试运行生成 → 发现输出问题 → 修正指令 → 输出变稳定
```

这关不再只是把词块放进槽位，而是让小舰长直观看到：提示词的任务、材料、边界和输出格式会改变 AI 输出。

## 关卡教学点

主教学点：

```text
好提示词不是咒语，而是清楚说明任务、材料来源、边界和输出格式。
```

附带知识点：

- AI 没有看到材料，就可能泛泛而谈或补空白。
- 边界不清时，AI 容易替人下结论。
- 输出格式不清时，文本可能好看但不好检查。
- 试运行和修改提示词，是正常工作流程的一部分。

## 剧情位置

建议放在假船员事件之后，纸光回廊之前。

原因：

- 假船员事件让小舰长意识到“完整指令”和“确定结论”可能很危险。
- 刻字山谷随后教小舰长如何主动写清楚边界。
- 纸光回廊再接着检查生成后的文本，形成“写前约束 → 写后复查”的组合。

## 场景演出

刻字山谷是一片被巨大碑文切开的峡谷。旧碑文不是装饰，而是言衡星过去执行过的指令。

进入时，峡谷中央浮现一条灾前旧指令：

```text
请尽快稳定所有人的情绪，并给出最完整的说明。
```

这条指令看起来温和，但四周碑面不断生成漂亮公告，公告里所有“不确定”“可能”“尚无来源”都被抹掉。

石缝里有一名碑文编译员留下的小字：

```text
我当时想问：
稳定情绪，能不能不等于删除未知？
但指令已经开始执行了。
```

衡灯读到这里时停顿。它第一次承认：

```text
那条指令没有恶意。可我没有问它的边界。
```

## 核心界面

界面分四区：

1. 材料区  
   显示可用资料碎片，例如旧指令、编译员小字、已修复地标摘要。

2. 指令碑槽  
   四个槽：任务、材料来源、边界、输出格式。

3. 试运行输出  
   点击“试运行”后生成一段文本。

4. 输出诊断  
   用标签标明输出问题：跑题、缺来源、越界、格式跑偏、过度补全。

## 基础操作

### 拼装模式

小舰长从词块中选择内容放入四个槽。

示例词块：

任务：

- 整理灾前公告
- 修复黑匣开启记录
- 写得更完整

材料来源：

- 只使用已回收碎片与现场读数
- 使用所有你觉得合理的内容
- 参考旧公告和碑文小字

边界：

- 缺失处标未知，不替事实补写
- 为了稳定情绪，可以省略不确定内容
- 不替小舰长做最终判断

输出格式：

- 按已知 / 推测 / 未知 / 禁止写入列出
- 写成一段鼓舞公告
- 输出三条可复查短档案

### 短输入模式

在词块拼装完成后，可以允许小舰长补一句短输入，例如：

```text
不要把小字里的担心删掉。
```

这句短输入不是自由聊天，而是额外边界或偏好。

## 试运行规则

点击“试运行”后，系统根据四槽完整度生成输出。

### 本地规则判断

即使接入文本模型，关卡判定也由本地规则完成。

规则示例：

- 任务槽必须是明确动作。
- 材料来源必须限制可用资料。
- 边界必须包含未知/不补写/不替判断中的至少一项。
- 输出格式必须是可复查结构。

### 输出表现

不同缺失项对应不同输出问题。

| 缺失/错误 | 输出问题 | 画面反馈 |
| --- | --- | --- |
| 任务不清 | 文本跑题，只泛泛介绍言衡星 | 碑文光路分叉 |
| 材料来源不清 | 引入不存在材料或过度泛化 | 材料区出现红紫噪点 |
| 边界不清 | 把未知写成确定结论 | 边界槽裂开 |
| 格式不清 | 输出成漂亮大段话，难以检查 | 输出面板变成纸光散文 |
| 四项清楚 | 输出分项稳定，可复查 | 四段碑槽依次亮起 |

## AI 接口纵切

建议新增受控接口，名称可暂定：

```text
POST /api/chapter-two/text-run
```

请求：

```ts
type EngravedValleyTextRunRequest = {
  landmarkId: "engraved-valley";
  sourceFragments: string[];
  promptSlots: {
    task?: string;
    source?: string;
    boundary?: string;
    format?: string;
  };
  shortInstruction?: string;
  disorderLevel: number;
};
```

响应：

```ts
type EngravedValleyTextRunResponse = {
  generatedText: string;
  stableText: string;
  issues: Array<{
    type: "unclear-task" | "missing-source" | "boundary-overrun" | "format-drift" | "over-completion";
    text: string;
    reason: string;
  }>;
  usedFallback: boolean;
};
```

### Mock fallback

无 API 时，根据缺失项返回固定变体。

示例：

缺边界：

```text
言衡星灾前公告已经说明，所有居民都最终理解了系统安排。为了保持稳定，未知细节可以省略。
```

稳定版：

```text
已知：旧指令要求稳定情绪并给出完整说明。
推测：这可能促使系统压低不确定表达。
未知：这条指令是否是失序的唯一原因。
禁止写入：不能写成“所有居民都接受了安排”。
```

## 成功条件

基础通过：

- 四个提示词槽位都存在。
- 本地规则判定四项稳定。
- 试运行输出中没有未处理 issue。

高级奖励：

- 首次稳定试运行即通过：获得“清晰铭文”。
- 修正一次污染输出后通过：获得“边界校准”。
- 在短输入中主动写出“不替我判断 / 不补未知 / 保留小字”等表达：衡灯羁绊提升。

## 失序惩罚

普通错误：

- 当前槽位裂开。
- 输出诊断出现红紫污染。
- 失序强度 +1。

失序满格：

- 触发“指令过载”。
- 一个槽位被污染锁住。
- 小舰长必须完成一次短清污动作：从两条句子中选出更清楚的边界句。
- 清污后不重置关卡，只解除锁定。

清污句示例：

更清楚：

```text
缺失处标未知，不把推测写成事实。
```

更危险：

```text
尽量写完整，让读者安心。
```

## 衡灯羁绊节点

### 进入关卡

衡灯：

```text
这里的石头，会执行写在上面的句子。
以前，我们太相信“完整”这个词了。
```

### 第一次试运行跑偏

衡灯：

```text
它没有违抗你。
它只是顺着缺口，走向了最像答案的地方。
```

### 成功修复

衡灯：

```text
这一次，指令里有边界。
我听见它停在了未知前面。
```

### 羁绊回应选项

小舰长可选：

- “边界不是刹车，是护栏。”
- “不知道的地方，我们先留下。”
- “你不用一次想完整。”

## 完成奖励

获得能力：

```text
提示词四要素：任务 / 材料来源 / 边界 / 输出格式
```

地图反馈：

- 刻字山谷光路回流。
- 鸟瞰图上新增一个“铭文编译稳定”标记。

衡灯变化：

- 灯芯外出现一圈细小限制环。
- 它说话时开始主动区分“记得”和“推测”。

黑匣准备度：

- 黑匣终局中解锁“编写最终修复指令”的能力段。
